# thesis-lab — 투자 논리 랩 (종목 탐색 → 재료·증거 → 실적 전달 → 스코어링)

"좋은 뉴스 → 매수"가 아니라 **뉴스가 실적과 주가로 전달되는 경로**를 단계별로 검증하는
9단계 프레임워크(현상 → 원인 → 산업 확인 → 병목 → 증거 → 실적 레버리지 → 상대 비교 →
주가 위치 → 촉매/반증)를 기존 수집 자산 위에서 자동화한 것.

결과 페이지: 알파노트 **분석 › 🧭 논리** (`docs/thesis.html`)

## 실행

```bash
cd thesis-lab
python build_thesis.py            # 전체 (첫 실행 5~7분, 이후 캐시로 1~2분)
python build_thesis.py --top 20   # 심화 분석 그룹 수 (업종·테마 각 기본 15)
python build_thesis.py --offline  # 네트워크 없이 캐시 + CSV 만으로 재계산

python thesis_report.py 000660                    # 종목 한 장 논리(마크다운)
python thesis_report.py --group 반도체와반도체장비   # 그룹 요약
python thesis_report.py --top 20                  # 자동점수 상위 20
```

자동 실행: `run_quant_data.ps1`(금 17:00 / 월말 17:00)이 collect → rs_build 뒤에 이 빌드를
돌리고 `docs/thesis.html`, `docs/thesis_data.js` 를 함께 커밋·배포한다.
평일에 갱신하려면 `python build_thesis.py` 를 수동 실행(리포트·뉴스·수급은 매일 바뀜, RS 는
주간 스냅샷 기준).

## 파이프라인과 데이터 소스

| 단계 | 질문 | 자동 지표 | 소스 |
|---|---|---|---|
| ① 관찰 | 무슨 일이 벌어지는가 | 그룹 종합 RS, 4주 RS 변화, 확산(RS≥70 비중), 1M 수익률 중앙값 | 퀀트데이터 주간 스냅샷(현재 + 4주 전) |
| ② 재료 | 왜 오르는가 | 리포트 제목·요약 키워드, 뉴스 헤드라인, X모니터·시황·주도섹터 블로그 문장 | 리포트서머리.xlsx, 네이버 뉴스 API, x-monitor/briefs/blog |
| ③ 산업 확인 | 개별인가 산업인가 | 확산도, 커버 종목 EPS(E) 상향 비중, OPM 확대 종목 비중 | 스냅샷 비교, 분기 실적 |
| ④ 병목 | 가격이 마진으로 가는가 | 최근 분기 OPM YoY(pp)·QoQ, 업종 OPM 확대 비중 | 네이버 분기 실적 API |
| ⑤ 증거 | 누가 확인해주는가 | 리포트 증거 계층 자동 태깅 L1 회사 › L2 애널 › L3 산업·경쟁사 › L4 고객사 › L5 데이터(수주·판가·출하·증설) + **DART 단일판매ㆍ공급계약 공시(60일, 계약금액·최근 매출 대비 %·계약상대·기간 파싱) = L5 실제 주문** | 리포트 텍스트 키워드, OpenDART list.json(거래소공시)·document.xml |
| ⑥ 실적 전달 | ASP→매출→마진→EPS | 매출·영업이익 YoY, 증분마진 ΔOP/ΔRev, 영업레버리지, EPS(E)·OP(E) 4주 변화, 다음 분기 컨센서스 | 분기 실적 + 스냅샷 비교 |
| ⑦ 상대 비교 | 누가 가장 많이 버는가 | 업종 내 매출 순위, Core/Beta(변동성·레버리지·규모 피어 백분위) | 스냅샷 + 분기 |
| ⑧ 주가 위치 | 얼마나 반영됐나 | 52주 고점 대비, MA200, 외국인+기관 20일 순매수 일수, 거래량 5/20일, PER(E) 업종 대비, PEG | 스냅샷 + 네이버 투자자 API |
| ⑨ 촉매·반증 | 다음은 무엇, 무엇이면 폐기 | 다음 분기 실적 D-day(분기말+30~45일), 마지막 리포트 경과일, 자동 반증 조건 | 분기 키 + 리포트 날짜 |

## 자동 채점 (15항목 × 0/1/2 = 30점)

산업 ①수요(업종 OP YoY(E) 중앙값 ≥20%/≥0) ②확산(RS≥70 비중 ≥50/≥30%) ③RS 수준·가속 ·
병목 ④종목 OPM YoY ≥+3pp/>0 ⑤업종 OPM 확대 비중 ≥60/≥40% · 증거 ⑥리포트 30일 ≥3건(또는 2건+TP상향)/≥1, 또는 60일 공급계약 공시가 매출 대비 합계 ≥10%(또는 2건 이상)이면 2
⑦업종 EPS(E) 상향 비중 ≥60/≥40% · 기업 ⑧업종 매출 3위 이내/상위 30% ⑨증분마진 ≥30% 또는 레버리지 ≥2x / >0·>1x
⑩커버리지+ROE(E)≥10·변동성<80% / 커버리지만 · 주가 ⑪52주 고점 -8~-35% & MA200 위 =2 (신고가 근접·-35~-50% 조정·MA200 하회 조정 =1)
⑫외인+기관 순매수 ≥60% 일수 & 거래량 ≥1.1x / ≥50% · 실적 ⑬EPS(E) 4주 ≥+5% / >0 · 밸류 ⑭PER(E) ≤ 업종 중앙 & PEG ≤1.5 / 하나 ·
촉매 ⑮실적 D-45 이내 또는 7일 내 리포트 / D-90 이내.

해석: 25~30 매우 강한 후보 · 21~24 적극 관심 · 17~20 Watchlist · 13~16 부족 · ≤12 보류.
자료 없는 항목은 0점(페이지에 "-" 표시). **수동 4항목**(공급 확대 난이도, 고객사 확인, Thesis Break 명확성, 손익비 2:1)은
페이지에서 선택하며 브라우저(localStorage)에 저장, 마크다운 복사에 포함된다.

임계값은 `scoring.py` 한 곳에 있다. 채점 기준을 바꾸면 `python build_thesis.py --offline` 으로 즉시 재계산.

## 심층 리포트 (`/thesis` 스킬)

Claude Code 에서 `/thesis SK하이닉스` 처럼 부르면 ① `thesis_report.py --pack` 데이터 팩 →
② 웹 검색으로 고객사·경쟁사·산업 데이터 증거 보강 → ③ 15단계 리포트 작성(30점 채점·Bull/Base/Bear) →
④ `publish_thesis.py` 로 `docs/thesis/<code>.md` + `index.json` 게시 → 커밋. 페이지 상단 "심층 투자 논리 리포트"
카드와 종목 상세에 본문이 렌더링된다(http 로 열 때만; file:// 은 fetch 불가). 날짜별 사본은 `docs/thesis/history/`.

## 산출물

- `docs/thesis_data.js` — `window.THESIS_DATA` (그룹·종목·증거·뉴스·점수)
- `output/스코어_YYYYMMDD.csv`, `스코어_latest.csv` — 종목별 자동점수. **실행일 기준**으로 쌓여 점수 히스토리의 원천이 된다
  (같은 날 재실행은 덮어씀). 빌더가 이전 파일을 읽어 종목별 `hist`(최근 12회)·전회 대비 변화·항목별 변화를 계산하고,
  페이지의 그룹 표(멤버 평균점수 Δ·상승/하락 종목 수), 기업 비교 표(Δ·추이 스파크라인), 종목 상세(전회 점수·항목별 Δ·추이)에 표시한다.
  파일을 지우면 그만큼 히스토리가 사라지므로 output/ 은 보존할 것(git 제외).
- `cache/quarter|trend|news/*.json` — API 캐시(TTL 5일 / 1일 / 1일), 재생성 가능
- `cache/dart_list/YYYYMMDD.json`(일자별 거래소공시 목록, 과거일 영구·오늘 6시간), `cache/dart_doc/<rcept>.json`(공시 원문 텍스트, 영구) — DART 키는 secrets.json `dart_api_key`

## 한계·주의

- 증거 계층 태깅은 키워드 규칙이라 "L5 데이터"가 실제 데이터 확인이 아닐 수 있다. 원문을 읽고 판단할 것.
- 매출 노출도(pure play 여부)·병목 구조·고객사 발언은 자동화가 어렵다 → 수동 항목.
- 테마 그룹의 종목 점수는 산업 항목(①②③⑤⑦⑭)을 테마 통계로 재채점한 값이고, 종목 상세는 항상 소속 업종 기준이다.
- 4주 추정치 변화는 주간 스냅샷 2개 비교(적자↔흑자 전환은 ±999 로 표기). 스냅샷이 1개뿐이면 공란.
- 분기 실적은 네이버 제공 6개 분기(실적 5 + 컨센서스 1)라 TTM 비교는 하지 않는다.
