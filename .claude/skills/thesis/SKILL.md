# /thesis — 종목 심층 투자 논리 리포트

목표: 사람이 직접 쓰지 않아도 SK하이닉스 예시 수준의 15단계 리포트가 나오게 한다.
**숫자는 데이터 팩을 우선**하고, 데이터 팩에 없는 정성 증거(고객사 발언·산업 데이터·경쟁사)는
**웹 검색으로 채우고 반드시 출처 링크**를 단다. 추정값은 추정이라고 표시한다.

베이스 폴더: `thesis-lab/` (프로젝트 루트 기준). 인자 `$ARGUMENTS` = 종목명 또는 6자리 코드.
여러 종목이면 쉼표로 구분해 순서대로 처리한다.

## 0. 사전 확인

1. `docs/thesis_data.js` 기준일 확인: 3거래일 이상 오래됐거나 없으면 먼저
   `python thesis-lab/build_thesis.py` (캐시 있으면 1~2분, 없으면 5~7분) 를 돌린다.
   사용자가 "빠르게"라고 하면 `--offline` 으로 재계산만 한다.
2. 인코딩: 파이썬 실행은 항상 `python -X utf8 ...`.

## 1. 데이터 팩 생성

```bash
python -X utf8 thesis-lab/thesis_report.py "<종목명 또는 코드>" --pack
```

출력(마크다운)을 전부 읽는다. 여기에 있는 것:
- 자동 15항목 채점과 근거, 점수 히스토리, 종합 RS·업종 RS·확산도
- 분기 실적 5개(매출·영업이익·OPM), 증분마진·영업레버리지, 컨센서스 FY1·다음 분기, 4주 추정치 변화
- PER(E)·PEG·PBR·업종 중앙값, 52주 고점 대비·MA200, 외국인+기관 20일 순매수·거래량 비율
- 다음 실적 D-day, 증권사 리포트 60일 요약(제목·요약·목표가), DART 수주·공급계약 공시(금액·매출 대비·상대)
- 업종 피어 비교표, 업종 증거 사다리(L1~L5), 재료 키워드, 매크로·주도섹터 텍스트 언급, 인과사슬 초안

종목이 없다고 나오면 코드 6자리로 다시 시도하고, 그래도 없으면 퀀트데이터에 없는 종목(스팩·신규상장)이라고 알린다.

## 2. 웹 검색으로 외부 증거 보강 (WebSearch, 필요시 WebFetch)

데이터 팩이 못 주는 것만 찾는다. 검색은 **6~10회 이내**, 최신(최근 1~3개월) 우선, 영문·한글 병행.

| 찾을 것 | 검색 예 | 리포트에서 쓰는 곳 |
|---|---|---|
| 고객사 발언(구매자) | `<고객사> earnings call <제품> shortage / demand`, `<고객사> 실적 컨퍼런스콜 <부품>` | STEP 5 Evidence L4 |
| 산업 가격·수급 데이터 | `TrendForce <제품> price 3Q26`, `<제품> 계약가격 전망`, 운임·판가·가동률 지수 | STEP 3 수요·공급, STEP 5 L5 |
| 경쟁사 발언·CAPEX | `<경쟁사> <제품> capacity expansion 2027`, `<경쟁사> 실적 발표 <제품>` | STEP 3 공급, STEP 7, STEP 13 |
| 회사 IR·실적 발표 | `<회사> 2Q26 실적 발표 <핵심 제품>`, 뉴스룸 | STEP 1·6 (L1로만 취급) |
| 컨센서스 상세 | `<회사> 컨센서스 12개월 선행 EPS` (한경·에프앤가이드·WiseReport) | STEP 8·11 |
| 다음 이벤트 | `<회사> 3분기 실적 발표일`, 가격 협상·신제품·인증 일정 | STEP 12 |

규칙
- 회사 자신의 주장(L1)보다 고객사(L4)·실제 데이터(L5)를 높게 평가한다. 같은 이야기가 여러 계층에서 나오는지 본다.
- 검색으로 얻은 숫자는 문장 끝에 `([출처명](URL))` 형식으로 출처를 단다. 데이터 팩 숫자는 "(thesis-lab)"이라고 표시하지 않아도 된다.
- 찾지 못한 항목은 "확인 못함"이라고 쓰고 지어내지 않는다.

## 3. 리포트 작성 (아래 STEP 순서·형식을 그대로)

파일: 스크래치패드에 `<code>_thesis.md` 로 먼저 쓴다. 한국어, 기관 애널리스트 톤, 결론 먼저.
분량은 A4 3~5장. 표·화살표 체인을 적극 사용. **모든 STEP 을 채운다**(자료 없으면 "확인 못함"으로라도).

```
# <종목명> 투자 논리 (기준일 <데이터 기준일>, 주가 <현재가>원)

## 0. 결론
> 한 단락: 산업 변화 → 병목 → 이 회사 수혜 → 실적 → 시장 반영 정도 → 핵심 반대 논리. 마지막에 **점수 XX/30**, 분류.

## STEP 1. 한 줄 투자 논리
> "[산업 변화]로 인해 [핵심 제품]의 [가격·물량·점유율]이 개선되고 있으며, 이것이 [매출/마진/EPS] 상승으로 이어질 가능성이 있지만 현재 시장은 이를 [충분히/부분적으로/거의] 반영하고 있다."

## STEP 2. What is happening?
회사 개별 호재 / 산업 전체 변화 / 매크로 / 일시적 반등 / 구조적 변화 구분. "왜 지금 움직이나".
기존 시장 논리 → 바뀐 구조를 텍스트 화살표 체인으로. 업종 RS·확산도·피어 움직임으로 개별 vs 섹터 판단(데이터 팩).
판단: 회사 개별 X% + 산업 구조 Y%.

## STEP 3. 산업의 수요·공급 구조
### 수요 — 이유, 최종 고객, 구조/사이클, 성장률, 고객 CAPEX, 주문·백로그, 재고 (검색 증거 + 출처)
### 공급 — 증가율, 신규 CAPEX, 가동 시점, 확대 소요 시간, 경쟁사 (검색 증거 + 출처)
결론: **수요 > 공급 / 수요 ≈ 공급 / 수요 < 공급**

## STEP 4. Bottleneck
가장 부족한 것(생산능력·원재료·기술·장비·인력·전력·인증·고객 승인…). 이 회사는 수혜자인가 피해자인가. 병목이 쉽게 안 풀리는 이유.

## STEP 5. Evidence Ladder
| Evidence | 내용 | 신뢰도 |
| 고객사(L4) | … | ★ |
| 경쟁사·산업(L3) | … | |
| 가격·수주 데이터(L5) | 데이터 팩의 DART 공급계약(금액·매출 대비)·리포트 L5 + 검색 산업 데이터 | |
| 회사(L1) | … | |
최소 3개 독립 증거. 여러 계층이 같은 방향인지 한 줄 판단.

## STEP 6. Earnings Transmission Chain
산업 변화 → ASP/물량 → 매출 → GM → 영업이익 → EPS 를 사업부별 체인으로.
데이터 팩 숫자로 검증: 최근 분기 매출 YoY·영업이익 YoY·OPM 변화·증분마진·영업레버리지, 컨센 FY1, 4주 추정치 변화, 다음 분기 컨센.
가능하면 "ASP +10% → 매출 +a% → OPM +bpp → OP +c% → EPS +d%" 로 숫자화(추정 표시), 어렵면 높음/중간/낮음.

## STEP 7. Why this company?
피어 3개 이상 비교표(데이터 팩 피어표 + 검색 정성): 산업 노출도·점유율·기술·가격 결정력·실적 레버리지·가시성·재무·밸류·베타 (★ 5점 척도).
성격 정의: Quality / Growth / Cyclical / Turnaround / Deep Value / High Beta / Earnings Leverage (복수 가능). Core/Beta 자동 분류도 언급.

## STEP 8. Expectations
컨센 매출·영업이익·EPS(FY1, 다음 분기), 4주 변화, 목표주가 분포(리포트), PER(E)·PBR vs 업종 중앙값.
"현재 주가는 어느 정도의 미래 실적을 이미 반영하고 있는가?" 에 한 단락으로 답한다.

## STEP 9. What is not priced in?
최대 3개. 각각 **발생 가능성(높/중/저) × EPS 영향(높/중/저)**.

## STEP 10. Price Context
52주 고점 대비, 1M/3M/6M 수익률(RS), MA200, 거래량 비율, 외국인+기관 20일 순매수(데이터 팩).
상태: **과매도 / 바닥 형성 / 초기 상승 / Breakout / 상승 추세 / 과열 / Distribution**. 펀더멘털과 일치 여부.

## STEP 11. Valuation
Forward PER(E)·PEG·PBR (+검색으로 EV/EBITDA·12MF PER 있으면). 과거 평균·피어·성장률 대비. "PER이 낮다 ≠ 싸다" — 사이클 피크 EPS 여부 판단. EPS 상승 가능성을 반영한 Forward 판단.

## STEP 12. Catalyst
### 1~3개월 / ### 3~12개월 — 각 항목 ★ 중요도. 다음 실적 D-day(데이터 팩)·가격 협상·신제품·수주·인증·정책·자사주.

## STEP 13. Thesis Break
최소 5개, 각각 **Early Warning Indicator** 포함. 자동 반증(EPS(E) 하향 전환·업종 RS 50 하회·OPM 축소·외인+기관 순매도·MA200 하회) + 산업 고유 조건.

## STEP 14. Bull / Base / Bear (12개월)
| | Bear | Base | Bull |
| 매출 | | | |
| 영업이익 | | | |
| EPS | | | |
| 적용 PER | | | |
| 적정주가 | | | |
| 현재 대비 | | | |
Base 는 컨센서스(데이터 팩 EPS(E))를 기준점으로. 각 시나리오 조건 3줄. 추정임을 표시.

## STEP 15. 30점 체크리스트
| 평가항목 | 점수 | 판단 | 자동점수 참고 |
15항목: 1 구조적 수요 / 2 수요>공급 / 3 병목 지속성 / 4 고객사 확인 / 5 경쟁사·산업 확인 / 6 실제 데이터 /
7 직접 노출도 / 8 EPS 레버리지 / 9 경쟁 우위 / 10 추정치 상승 / 11 Consensus beat 가능성 / 12 Valuation /
13 주가 확인 / 14 Catalyst / 15 Risk-Reward. 각 0/1/2. 마지막 열에 thesis-lab 자동 항목(①~⑮) 중 대응되는 점수를 적어 차이를 드러낸다.
**총점: XX / 30** — 26~30 Strong Buy Candidate · 22~25 Attractive · 18~21 Watchlist · 14~17 Weak · 0~13 Avoid

## 최종 결론
### Investment Thesis (3~5문장) / ### Why Now? / ### Key Earnings Driver (3개) / ### What Market Is Missing /
### Best Evidence (3개) / ### Biggest Risk (3개) / ### Next Catalyst (3개) / ### Thesis Break / ### Score **XX / 30**
분류: **Core Holding / Tactical Buy / High Beta Trade / Watchlist / Avoid** (굵게, 이 문구 그대로 — index 가 파싱한다)
> "이 종목에서 가장 중요한 것은 ______이며, 앞으로 ______가 확인된다면 현재 투자 논리는 더욱 강해질 것이다."

## 매일 볼 지표 6개
데이터 팩·검색에서 고른 모니터링 지표(가격·점유율·백로그·마진·EPS 컨센·수급 등). 가장 중요한 단일 지표 1개 명시.

## 출처
검색 출처 번호 목록 [n]: 제목 — URL
```

추가 원칙: 좋은 점만 찾지 말고 반대 논리를 반드시 검토 · 주가가 올랐다고 펀더멘털이 좋다고 하지 않는다 ·
회사 발표를 그대로 받아들이지 않는다 · 컨센서스와 내 전망의 차이를 가장 중요하게 본다 · "산업이 좋다"에서 끝내지 말고 EPS까지 연결.
자동 15항목 점수와 내 채점이 3점 이상 다르면 STEP 15 아래에 왜 다른지 두 줄 적는다.

## 4. 게시

```bash
python -X utf8 thesis-lab/publish_thesis.py <code> "<스크래치패드>/<code>_thesis.md"
```

→ `docs/thesis/<code>.md`, `docs/thesis/index.json`, `docs/thesis/history/<code>_YYYYMMDD.md` 가 생긴다.
점수·분류를 못 찾았다고 나오면 `--score N --cls "Core Holding"` 을 붙여 다시 실행한다.

커밋(푸시는 하지 않음 — 17:30 자동화가 pull·push):
```bash
git add docs/thesis && git commit -q -m "thesis: <종목명> 심층 투자 논리 <YYYY-MM-DD> (<점수>/30, <분류>)"
```
브랜치가 main 인지 먼저 확인한다(`git rev-parse --abbrev-ref HEAD`).
